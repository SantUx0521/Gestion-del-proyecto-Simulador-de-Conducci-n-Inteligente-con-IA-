| Definición del problema: |  |
| :---- | :---- |
| Los procesos de aprendizaje y práctica de conducción pueden presentar dificultades para identificar de manera objetiva los errores cometidos durante una sesión. En una práctica tradicional, el estudiante puede recibir retroalimentación general, pero resulta difícil registrar y analizar de forma detallada aspectos como frenadas, aceleraciones, cambios de marcha, giros, choques o incumplimiento de señales de tránsito.  |  |
| **Definición de los objetivos:** |  |
| **Objetivos** | **Criterios de evaluación de los objetivos** |
| Desarrollar un prototipo físico basado en ESP32 y seis botones que permita representar acciones básicas de conducción como girar, acelerar, frenar y cambiar de marcha. | El prototipo deberá detectar correctamente las acciones realizadas mediante los botones y transmitirlas al sistema. |
| Desarrollar una interfaz web que represente mediante una animación las acciones realizadas por el usuario durante la simulación. | La interfaz deberá mostrar de forma comprensible las acciones ejecutadas y el estado del vehículo durante la simulación. |
| Registrar los datos generados durante las sesiones de conducción para su posterior análisis. | El sistema deberá almacenar las acciones realizadas y los eventos relevantes ocurridos durante cada sesión. |
| Implementar un modelo o mecanismo de análisis basado en IA que permita identificar errores o comportamientos inadecuados durante la conducción. | El sistema deberá identificar determinados eventos definidos previamente, como choques, aceleraciones ante un STOP, cambios de marcha incorrectos o maniobras inadecuadas. |
| Generar una retroalimentación al finalizar la simulación con los principales errores identificados y recomendaciones para mejorar la conducción. | El sistema deberá presentar un resumen de la sesión y recomendaciones relacionadas con los errores detectados. |
| **Alcance:** |  |
| **Dentro del alcance** | **Fuera del alcance** |
| Diseño y construcción de un prototipo físico utilizando un ESP32 y seis botones para representar acciones básicas de conducción. Desarrollo de una página web para visualizar la simulación. Comunicación entre el ESP32 y la aplicación web. Registro de los datos generados durante las sesiones. Implementación de un modelo o mecanismo de IA para analizar los datos de conducción. Generación de un informe básico con errores y recomendaciones. Pruebas funcionales del prototipo. | Desarrollo de un vehículo físico real. Integración con automóviles reales. Simulación de conducción con gráficos 3D avanzados. Desarrollo de una aplicación móvil nativa. Reconocimiento mediante cámaras o sensores externos. Evaluación o certificación oficial de conductores. Uso del sistema como sustituto de una escuela o instructor de conducción. |
| **Suposiciones:** |  |
| Se supone que el ESP32 contará con conexión estable para transmitir las acciones realizadas por el usuario al sistema. Se supone que los seis botones permitirán representar adecuadamente las acciones básicas definidas para la simulación. Se supone que el usuario tendrá acceso a un computador con navegador web para utilizar el simulador. Se supone que los datos generados durante la simulación podrán ser registrados y almacenados correctamente. Se supone que las reglas y eventos utilizados para determinar los errores de conducción podrán ser definidos previamente. Se supone que se contará con los conocimientos y recursos técnicos necesarios para desarrollar el prototipo. Se supone que el modelo o mecanismo de IA podrá utilizar los datos recopilados para generar un análisis básico del desempeño del usuario. |  |
| **Restricciones:** |  |
| El proyecto deberá desarrollarse dentro del tiempo establecido para el proyecto académico. El prototipo estará limitado a un ESP32 y seis botones como elementos principales de interacción física. La simulación representará únicamente un conjunto limitado de acciones y situaciones de conducción. El sistema requerirá un computador y un navegador web para visualizar la simulación. El modelo de IA estará limitado al análisis de los datos generados por el simulador y no realizará reconocimiento visual del entorno. |  |
| **Factores generales de riesgo:** |  |
|  **Riesgo Consecuencia Responsable** Dificultades en la comunicación entre el ESP32 y la página web. Las acciones realizadas mediante los botones podrían no reflejarse correctamente en la simulación. Equipo de desarrollo. Fallas en los botones o conexiones del prototipo. El sistema podría registrar acciones incorrectas o no registrar algunas acciones. Equipo de desarrollo. Errores en el registro de datos. El análisis posterior podría presentar resultados incorrectos. Equipo de desarrollo. Dificultad para desarrollar el modelo de IA. El sistema podría no identificar correctamente los errores de conducción. Equipo de desarrollo. Complejidad del simulador. El proyecto podría superar el tiempo o los recursos disponibles. Gerente del proyecto. Errores en la lógica de conducción. La simulación podría generar eventos o evaluaciones incorrectas. Equipo de desarrollo. Problemas de integración entre hardware, web e IA. El prototipo podría no funcionar como un sistema integrado. Equipo de desarrollo.  |  |
